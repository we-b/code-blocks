これから「タスクの複製機能」を実装します。以下の仕様書を元に、この機能のテストケースを網羅的に洗い出し、カテゴリ別に整理してください。
単体テスト（サービスクラスのメソッド）と結合テスト（APIリクエスト）の両方の観点からテストケースを挙げてください。

# 機能仕様
- 既存のタスクをコピーして、新しいタスクを作成する
- エンドポイント: POST /tasks/{id}/duplicate （{id}にはコピー元のタスクIDを指定）
- 属性の引き継ぎ:
  - 指定されたタスクの title, content, genre_id, priority をそのまま引き継ぐ。
- 特別な処理:
  - title: 末尾に「(コピー)」という文字列を自動的に追加する。
  - status: 元のタスクの状態に関わらず、必ず「todo」（初期ステータス）になる。
