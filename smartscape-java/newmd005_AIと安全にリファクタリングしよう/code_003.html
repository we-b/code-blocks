TaskController の責務分析

| 責務                | 該当コード                    |
|---------------------|------------------------------|
| HTTPリクエストの受付  | @GetMapping, @PostMapping 等 |
| バリデーション       | errors.add("タイトルは必須です") 等 |
| エンティティの組み立て | new Task() + setter 呼び出し |
| データベースへの保存   | taskRepository.save(task)   |
| レスポンスの組み立て   | Map<String, Object> の手動生成 |
| エラーハンドリング     | ResponseEntity.status(BAD_REQUEST) |

問題点:
1. 単一責任の原則に違反 — 6つ以上の責務が1クラスに集中
2. コードの重複 — レスポンスMapの組み立てが4か所で繰り返されている
3. テストの困難さ — ビジネスロジックがControllerに直書きされているため、
   単体テストが書きにくい
4. 変更への脆弱性 — バリデーションルールの変更が Controller の修正を必要とする
